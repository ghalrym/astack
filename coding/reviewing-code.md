
# Reviewing code

Rules for reviewing code:

1. Follow all other skills for the relevant subjects in the codebase
2. K.I.S.S (Keep it stupid simple) - if things can be simplified suggest doing so


# Business Scope:

1. How will this code operate under load?
2. If an exception or crash occurs how is it handled?


# Personal Scope

1. Understand that only 1 or 2 users will be using this project and do not scope review to industy standards, lean more into clean coding rather than making the user worry about scale.
